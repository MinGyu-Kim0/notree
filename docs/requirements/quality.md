# 품질 요구사항

## QUR-001 AI 판단 품질 검증

AI 품질 > 내용·평가 · 필수 · 담당 전원 · 요청 · 관련 SFR-018, SFR-035

서비스는 노트·답변·변경·평가의 의미적 품질을 대표 사례로 검증해야 한다.

**수용 기준**

1) 근거 부족·오개념·부분 답안·무변경·삭제 근거·다중 출처·잘못된 전제 사례를 포함한다.
2) 호출 성공이나 모델 스스로의 채점만으로 통과 처리하지 않는다.
3) 평가 세트는 강의 노트·과목 노트 업데이트·Q&A·문제 생성·채점 5개 기능 각 30건(총 150건)이며, 30%는 조정에 쓰지 않는 확인용으로 분리한다.
4) 사람 평가자 2명 이상이 20%를 교차 채점하고, 평가자 간 일치도가 가중 카파 0.6 미만이면 평가 기준부터 고친다.
5) 출시 차단(0건이어야 함): 출처 위조, 다른 사용자 자료 노출, 사용자 편집 파괴, 무효 근거로 답변·채점, 미완성 답변 저장, 잘못된 전제의 노트 저장.
6) 초기 합격 목표: 평가 기준 통과율 90% 이상, 채점 일치도 가중 카파 0.7 이상, 복습 등급의 성공·실패 일치 95% 이상.
7) 정책·모델·프롬프트·검색·평가 기준·기능이 바뀌면 다시 평가한다.

**비고**: [MVP] 6)은 목표치이며 달성 여부는 미검증.

## QUR-002 최신 사용자 수정 보호

신뢰성 > 편집 충돌 · 필수 · 담당 이근욱 · 요청 · 관련 SFR-009, SFR-020

시스템은 오래된 AI 결과가 최신 사용자 편집을 덮어쓰지 않도록 해야 한다.

**수용 기준**

1) AI 처리 도중 같은 부분을 수정한 경우 재판단·충돌 표시를 수행한다.
2) 최신 사용자 편집 내용이 보존된다.
3) 업데이트 실행 중에는 과목 노트 편집을 막고, 작업이 비정상 종료되어도 편집 잠금은 60초 안에 풀린다(초기값).
4) 늦게 끝난 이전 작업의 결과는 반영되지 않는다.

**비고**: [MVP]

## QUR-003 연결 종료와 작업 상태 구분

신뢰성 > 연결·복구 · 필수 · 담당 김민규 · 요청 · 관련 SER-001, SFR-002, QUR-008

시스템은 화면 연결 종료·녹음 종료·명시적 작업 취소를 구분해야 한다.

**수용 기준**

1) 화면 연결 종료·녹음 종료·사용자 취소·시스템 중지를 구분하고, 중지·취소에는 주체와 원인을 기록한다.
2) 재접속 후 보존된 진행 상황과 결과를 확인한다.
3) 음성 누락 가능 구간을 표시한다.
4) 서버에 도달하지 못한 질문은 다시 입력하도록 안내한다. 저장된 질문은 다시 입력할 필요가 없다.
5) 연결이 끊기면 최초 시도 후 최대 3회 다시 연결하고(1·2·4초 간격), 모두 실패하면 녹음을 시스템 중지하고 보존된 음성의 복구 업로드를 제공한다. 다시 연결된 뒤 60초 동안 안정적이어야 실패 횟수를 초기화한다.
6) 예기치 않은 연결 끊김이 5분 이어지면 녹음 세션을 종료한다. 사용자가 일시정지한 경우에는 적용하지 않는다.

**비고**: [MVP] v0.3.1 대비: '재시도 3회 후 취소'를 '최초 + 재시도 3회 후 시스템 중지'로 구체화. 4)의 재입력 안내는 질문 보관 결정으로 서버에 도달하지 못한 질문에만 해당.

## QUR-004 재시도 시 중복 반영 방지

신뢰성 > 중복 방지 · 필수 · 담당 김민규 · 요청 · 관련 SFR-020, SFR-036

시스템은 같은 작업의 재시도로 결과를 중복 반영하지 않아야 한다.

**수용 기준**

1) 저장 직후 장애를 유발하고 재실행해도 노트 삽입·관찰·예약이 한 번만 반영된다.
2) 실패 단계와 재시도 결과를 구분한다.
3) 사용자가 요청한 재평가는 재시도와 구분해 새 평가 버전으로 처리한다.
4) 외부 서비스 호출 하나당 최대 4회(최초 + 재시도 3회, 내부 재시도 포함)이며, 인증 오류·잘못된 요청·정책 거절·사용자 취소는 재시도하지 않는다. 작업 실행 중 장애로 다른 실행이 이어받는 경우는 재시도와 따로 세고, 작업 하나당 3회까지다(초기값).

**비고**: [MVP] v0.4.4: 4)를 '작업 하나당'에서 '외부 서비스 호출 하나당'으로 고침. Q&A처럼 한 작업이 여러 번 호출하는 경우 작업 단위 상한은 정상 동작도 막기 때문. 재시도는 호출 단위(SDK)로만 하고, 장애 인계 상한을 따로 둠(ADR-0017).

## QUR-005 지원 환경의 학습 흐름

사용성 > 지원 환경 · 필수 · 담당 전원 · 요청 · 관련 SFR-002, SFR-009

서비스는 합의된 기기·브라우저에서 주요 학습 흐름을 사용할 수 있어야 한다.

**수용 기준**

1) 녹음·노트 편집·질문·복습의 대표 흐름을 확인한다.
2) 키보드만으로 대표 흐름을 수행할 수 있고, 포커스가 보이며, 상태를 색으로만 구분하지 않는다.
3) 지원 환경: 데스크톱 Chrome·Edge 최신 2개 주요 버전, Windows 11·지원 중인 macOS·Ubuntu LTS. 모바일은 조회·복습을 지원하며 모바일 녹음은 지원 표시를 하지 않는다.
4) 실제 시험을 통과한 조합만 지원으로 표시한다.

**비고**: [MVP] 키보드 조작 점검(2)을 권장으로 낮추려면 우선순위 변경 절차(개정 이력 기록)를 거친다. 비고만으로 제외하지 않는다.

## QUR-006 개인맞춤 판단 평가

개인화 > 효과 평가 · 필수 · 담당 임서연 · 요청 · 관련 SFR-028, SFR-033

서비스는 사용자 이력에 따른 복습 결정의 적절성을 평가해야 한다.

**수용 기준**

1) 같은 개념·다른 수행 이력의 사례 15쌍을 비교한다.
2) 내용·유형·난이도·시점의 차이가 근거와 일치하는지 사람이 판정하며, 초기 목표는 80% 이상이다.
3) 성적 향상은 보장 항목으로 평가하지 않는다.

**비고**: [MVP] 목표치이며 달성 미검증.

## QUR-007 작업·AI 호출 추적

유지보수성 > 운영 추적 · 권장 · 담당 김민규 · 요청 · 관련 PER-003, SER-001, SER-003

서비스는 장기 작업과 외부 AI 호출의 상태·오류·사용량을 운영자가 추적할 수 있어야 한다.

**수용 기준**

1) 작업별 단계·소요 시간·실패 사유를 조회한다.
2) 외부 호출별 사용량과 예상·실제 비용을 집계한다.
3) 기록에 질문 원문과 인증 키가 포함되지 않는다.

**비고**: [MVP]

## QUR-008 짧은 연결 끊김 시 음성 보존

신뢰성 > 연결·복구 · 권장 · 담당 김민규 · 요청 · 관련 QUR-003, SIR-001

시스템은 녹음 중 짧은 네트워크 끊김 동안의 음성을 보존해 연결 회복 후 전송해야 한다.

**수용 기준**

1) 끊김 동안 수집한 음성이 회복 후 같은 강의에 이어 붙는다.
2) 브라우저는 서버 저장이 확인될 때까지 최대 60초 또는 32MiB의 음성을 보관하며, 한도를 넘은 구간은 누락 구간으로 표시한다(초기값).
3) 다시 연결하는 동안(QUR-003) 음성을 보존한다.
4) 브라우저 탭이 닫히면 보관 중인 음성이 사라질 수 있음을 안내한다.

**비고**: [MVP]
