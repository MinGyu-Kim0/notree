# 도메인 문서

엔지니어링 스킬이 코드베이스를 살필 때 이 레포의 도메인 문서를 어떻게 읽는지 정한다. 요구사항, 설계, 스키마 같은 다른 문서의 위치는 `AGENTS.md`의 '문서 지도'를 따른다.

## 살피기 전에 읽을 것

- 레포 루트의 **`GLOSSARY.md`**
- **`docs/adr/`**: 작업할 영역에 걸린 ADR

## 구조

단일 컨텍스트다.

```
/
├── GLOSSARY.md
├── docs/adr/
│   ├── 0001-redis-streams-worker.md
│   └── ...
└── backend/
```

## 용어집의 말을 쓴다

결과물(이슈 제목, 리팩터링 제안, 가설, 테스트 이름)에서 도메인 개념을 부를 때는 `GLOSSARY.md`에 정의된 용어를 그대로 쓴다. 용어집이 피하라고 한 동의어로 바꾸지 않는다.

필요한 개념이 용어집에 없으면 신호다. 프로젝트가 쓰지 않는 말을 지어내고 있거나(다시 생각한다), 실제로 빠진 용어다(`/domain-modeling`에 넘길 거리로 적어 둔다).

## ADR과 어긋나면 밝힌다

결과물이 기존 ADR과 다르면 말없이 덮어쓰지 말고 드러낸다.
