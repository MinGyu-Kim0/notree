# AI 결과는 근거 버전과 세대 번호를 커밋 순간에 비교해 반영한다

AI 작업은 수십 초에서 수 분 걸린다. 그 사이 근거가 삭제·수정·이동되거나 작업이 취소될 수 있다. 정의서는 다섯 군데(SFR-007·016·020·034·035)에서 "반영하는 순간 원자적으로 확인"을 요구한다. 그래서 모든 AI 결과 저장에 같은 패턴을 쓴다. 결과에는 사용한 근거의 (자료 ID, 버전) 목록을 붙인다. 반영 대상(과목 노트, 강의 등)에는 세대 번호를 두고, 삭제·취소·잠금 해제 때 올린다. 커밋 트랜잭션에서 대상 행을 잠근 뒤, 근거 버전과 세대 번호가 작업 시작 때 그대로인지 비교한다. 하나라도 다르면 반영하지 않고 다시 계산하도록 작업을 넣는다. 이 패턴은 `platform`에 한 번만 구현하고 모든 모듈이 같이 쓴다.

## Consequences (2026-11-18 추가)

- 같은 트랜잭션에서 실행 시도 번호(ADR-0018)와, 작업이 읽었던 대상 노트 버전도 비교한다. 노트 버전이 다르면 다른 AI 작업이나 사용자가 먼저 바꾼 것이니 최신 노트 기준으로 다시 계산한다.
- 다르다고 모두 다시 계산하지 않는다. 근거가 수정됐거나 노트 버전이 바뀐 경우에만 다시 계산한다. 근거 삭제, 권한 상실, 사용자 취소, 세대 번호 증가는 작업을 끝내고 다시 넣지 않는다.
- 다시 계산하는 작업도 인계 상한(ADR-0017) 안에서 돈다.
- 사용자가 고친 블록은 보존하고 AI 결과는 확인이 필요한 변경안으로 남긴다(SFR-022, QUR-002). 사용자가 승인해서 반영할 때도 이 확인을 다시 거친다.
- Q&A 답변 저장만 예외다([ADR-0022](0022-qa-followup-stages-in-one-job.md)). 근거가 수정·삭제됐으면 다시 생성하지 않고 `answer_status = 'evidence_changed'`('근거 변경됨')로 저장해 질문을 보존하며, 후속 단계(반영·관찰)는 돌리지 않는다. SFR-016 8)이 이 처리를 허용한다. 최종 노트(SFR-007 5)), 노트 반영(SFR-020 2)), 문제 활성화(SFR-034 3)), 채점 반영(SFR-035 6))은 원문이 '반영하지 않음'을 요구하므로 위 규칙을 그대로 따른다.
