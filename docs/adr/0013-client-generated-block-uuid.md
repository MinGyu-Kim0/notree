# 블록 ID는 편집기가 만드는 UUIDv7로 한다

블록은 위치가 바뀌어도 같은 블록으로 식별돼야 하고(DAR-002 1), Q&A 반영 위치도 블록 ID로 지정한다(SFR-019 2). 다른 테이블은 모두 서버가 만드는 `bigint`지만, 블록만은 편집기가 새 블록을 만드는 순간 ID가 있어야 한다. 서버 `bigint`를 쓰면 편집기가 새 블록에 임시 ID를 붙였다가 저장 응답으로 진짜 ID를 받아 바꿔 끼워야 하고, 그 사이 편집이 이어지면 동기화가 복잡해진다. 그래서 `blocks.id`는 `uuid`로 두고 편집기가 만든다. 시간순으로 정렬되는 v7을 써서 무작위 UUID의 인덱스 분산 문제를 줄인다.

## Consequences

- 서버는 받은 UUID가 v7 형식인지, 이미 다른 블록이나 다른 사용자에게 쓰이지 않았는지 검사한다. 복합 FK와 RLS 덕분에 다른 사용자의 블록 ID로는 참조할 수 없다(ADR-0010).
- AI가 만드는 블록은 서버가 UUIDv7을 만든다.
- 블록 리비전과 노트 버전은 그대로 `bigint`다. 노트 버전은 리비전 ID 배열이라 블록 ID가 uuid여도 영향이 없다.
