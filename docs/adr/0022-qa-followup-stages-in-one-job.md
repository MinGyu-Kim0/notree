# Q&A 후속 처리는 같은 작업 안의 단계로 실행하고, 계정 동시 실행 한도는 사용자가 시작한 작업에만 건다

Q&A는 답변을 저장한 뒤에 반영 판단·위치 결정·정책 검사와 관찰 추출을 한다. 후속 처리가 실패해도 답변은 남아야 하고, 실패한 단계만 다시 실행해야 한다(SFR-021, SFR-043). 대안은 후속 처리를 별도 작업(반영, 관찰)으로 떼는 것이었다. 답변이 끝나면 Q&A 한도를 바로 반납하고 단계마다 따로 재시도할 수 있지만, 워커가 질문마다 작업 2개를 새로 등록하게 된다. 그러면 이 작업들도 계정 동시 실행 한도(PER-003 5)를 받아야 해서, 실행 허가, 한도가 찰 때의 대기열, 자리가 비면 다시 보내기, 인계 때 자리 이어받기, 실시간 요약 예외를 모두 새로 만들고 시험해야 한다. 그래서 `qa_answer` 작업 하나가 세 단계를 순서대로 실행한다. 답변 단계는 답변 그래프(LangGraph)로 답변을 생성해 저장한다. 반영 단계는 반영 판단·위치 결정·정책 검사를 한다. 관찰 단계는 관찰을 추출한다. 반영·관찰 단계는 OpenAI SDK를 직접 부르는 일반 함수다. 각 단계는 결과와 완료 표시(`messages.answer_status`, `reflect_status`, `learner_status`)를 한 트랜잭션으로 커밋한다. LangGraph 체크포인터가 아니다. 그래프 상태는 저장하지 않고, 어느 단계가 끝났는지만 도메인 행에 남긴다.

## Consequences

- 인계나 재시도 때는 완료 표시를 보고 남은 단계만 한다. 재시도는 새 `qa_answer` 작업 행이 같은 답변 메시지를 대상으로 하며, 새 답변 메시지는 답변 단계가 실패했을 때만 만든다(2026-11-19). 답변 단계가 끝나지 않았으면 저장된 질문으로 처음부터 하고(SFR-043 2), 끝났으면 답변을 다시 만들지 않고 반영·관찰 단계만 한다. 이 단계들에 필요한 입력(질문, 답변, 근거, 현재 노트)은 모두 DB에 있다.
- 반영·관찰 단계가 실패하면 그 단계 상태만 `failed`가 되고 답변은 남는다(SFR-021 1·2). 두 단계는 `answer_status = 'completed'`일 때만 돈다. 관찰은 `observations.dedupe_key`로 한 번만 들어간다(QUR-004 1).
- 반영·관찰 단계가 도는 10~20초 동안 계정당 Q&A 1개 한도를 그대로 잡는다. 그동안 다음 질문은 '답변 정리 중'으로 보내기를 막는다.
- 계정 동시 실행 한도(녹음 1, Q&A 1, AI 작업 전체 2)는 사용자가 요청해서 시작하는 작업(녹음, Q&A, 채점, 사용자가 누른 재생성·재시도)에만 건다. 그 요청을 받는 `api`·`realtime`이 작업 등록 트랜잭션에서 `users` 행을 잠그고 센다. 시스템이 이어서 만드는 작업(실시간 요약, 최종 노트, 과목 노트 업데이트, 검색 자료 갱신)은 종류별 상한(강의당 실시간 요약 실행 1·대기 1, 과목 노트당 실행 1·재개 대기 1·대기 1)과 Q&A·배경 작업의 워커 동시 실행 수(ADR-0017)로 묶는다. PER-003 5) 원문은 시스템 작업의 포함 여부를 정하지 않으므로 요구사항 변경안으로 확정한다.
- PER-004 4)의 질문 1건당 누적 입력 64k·출력 6k·90초는 답변 단계에 건다. 반영·관찰 단계는 사용자가 기다리는 구간 밖이라 호출마다 timeout과 비용 예약으로 묶는다. 이것도 요구사항 변경안으로 확정한다.
- 반영·관찰 단계의 시간은 합계 30초이고, `qa_answer` 작업의 AI 호출은 단계와 상관없이 모두 재시도 1회다(2026-11-19, 11-18 회의 결정). 두 시간은 SDK 재시도와 그 대기를 포함한 단계 전체의 마감이고, 마감을 넘긴 단계와 그 뒤 단계만 `failed`가 된다. 답변 90초 + 후속 30초 = 120초가 회수 루프의 Q&A 기준(`STALLED_QA` 3분)보다 짧아야 정상 Q&A가 `stalled`로 끝나지 않는다. 배경 작업처럼 재시도 2회에 timeout을 넉넉히 주면 이 합이 3분을 넘을 수 있다.
- 사용자가 많아져 Q&A 한도 점유가 문제가 되면 반영·관찰 단계를 별도 작업으로 떼고 실행 허가를 만든다. 단계 경계와 완료 표시가 그대로라 옮기기 쉽다.
