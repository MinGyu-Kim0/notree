# 노트는 블록 리비전과 노트 버전으로 저장하고, 출처는 블록의 숨은 속성으로 둔다

출처를 본문에 넣으면 노트가 읽기 어려워지고, 노트 전체를 버전으로만 저장하면 블록마다 근거를 붙이기 어렵다. 그래서 두 층으로 나눈다. `block_revisions`는 블록 하나의 내용과 근거 목록을 바꾸지 않는 행으로 쌓는다. `note_versions`는 (블록 ID, 리비전)의 순서 목록이다. 옛 버전을 열면 그때의 근거까지 함께 보인다. 비교는 리비전끼리, 복원은 옛 목록을 복사한 새 버전으로 한다. 블록은 문단, 제목, 목록 항목, 코드, 표, 보강 블록 단위이고, 문장 단위 출처는 두지 않는다. 화면에서는 출처를 기본으로 숨긴다. 블록을 선택하면 여백 칩, "출처 보기"를 켜면 각주로 보여주고, "갱신 필요"와 "출처 삭제됨"만 배지로 붙인다. AI는 블록과 근거 ID를 구조화된 출력으로 낸다. 서버는 근거 ID가 그 작업에 넣어 준 자료 안에 있는지 검증해, 출처 위조 0건(QUR-001)을 코드로 보장한다.

## Consequences (2026-11-18 추가)

- 이 검증이 보장하는 건 "근거 ID가 실제 입력 안에 있다"까지다. 인용한 근거가 그 문장을 실제로 뒷받침하는지는 보장하지 않는다. 그건 `evals/`의 근거 타당성 평가로 따로 잰다.
- 블록의 자식 관계(들여쓰기)는 노트 버전 항목의 깊이로 저장한다([ADR-0020](0020-tiptap-flat-blocks-with-depth.md)).
- 웹 검색 근거는 우리가 넣어 준 자료가 아니므로, OpenAI 웹 검색 도구 응답의 인용 목록(URL)을 그 작업의 입력으로 본다. 인용 목록에 있는 URL만 `citations(kind='web')`로 저장하고, 답변 본문에만 나온 URL과 우리가 넘기지 않은 내부 ID는 버린다. 웹 검색을 별도 노드로 떼거나 웹 출처에 임시 ID를 발급하지 않는다.
