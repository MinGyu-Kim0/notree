# Q&A와 과목 노트 업데이트는 LangGraph 그래프로 만들고, 모델 호출은 OpenAI SDK로 직접 한다

> 상태: 일부 대체됨(2026-11-19). 과목 노트 업데이트의 재개 방식(체크포인터 없이 단계 완료 기록)은 [ADR-0023](0023-course-update-checkpointer-and-interrupt.md)(Postgres 체크포인터와 interrupt)으로 바뀌었다. Q&A 그래프는 그대로 체크포인터 없이 돈다.

과제의 요점은 AI 에이전트 서비스지만, Q&A에서 자료를 찾고 답하고 노트 반영을 판단하는 순서는 대부분 정해져 있다. AI가 매번 도구를 고르는 자유 에이전트로 만들면 호출이 늘어 PER-004의 최초 표시 p95 10초가 빠듯해지고, 같은 질문에도 경로가 흔들려 QUR-001 평가로 검증하기 어렵다. 그래서 흐름은 그래프로 고정하고, 결과에 따라 다음 행동이 갈리는 네 지점에서만 LLM이 판단하게 한다. 질문 분석(검색이 필요한가), 충분성 판단(재검색·웹 검색·확인 질문·상충 확인), 반영 판단(필요·불필요·보류), 위치 결정(블록을 더 읽을까)이다. 자동 반영 여부는 LLM이 아니라 코드의 정책 검사(SFR-020)가 정한다. LangChain은 쓰지 않는다. 제공사가 OpenAI 하나이고, LangChain이 주는 기성 에이전트·도구 헬퍼·스트리밍 연동이 이 구조에서는 필요 없어서다. LangGraph 노드 안에서 OpenAI SDK를 직접 부른다. COR-002가 채택한 것도 LangGraph이며 LangChain은 요구사항에 없다.

## Consequences

- Q&A 그래프는 체크포인트를 DB에 두지 않고 메모리에서만 돈다(SER-001 4). 그래프는 답변 저장까지다(2026-11-18 변경, [ADR-0022](0022-qa-followup-stages-in-one-job.md)). 반영 판단·위치 결정·정책 검사와 관찰 추출은 같은 `qa_answer` 작업 안에서 그래프 밖 일반 함수로 이어서 돈다. 반영 판단과 위치 결정은 여전히 LLM이 판단하는 지점이지만 그래프 노드는 아니다. 결과만 `messages`, `citations`, `note_changes`, `observations`에 저장한다. 사용자가 기다리는 구간은 답변 생성까지라 뒤 단계가 실패해도 답변은 남는다(SFR-021 2).
- 루프는 재검색 최대 2회, 위치 결정의 블록 추가 조회 최대 1회로 끊는다. 질문 1건의 누적 토큰과 시간은 PER-004 4)를 따르고, 답변 단계에 건다(ADR-0022).
- 과목 노트 업데이트 그래프는 Postgres 체크포인터로 재개하고, 의미 충돌은 `interrupt`로 사용자 확인을 받는다(2026-11-19 변경, [ADR-0023](0023-course-update-checkpointer-and-interrupt.md)). 이중 반영은 부작용이 있는 반영 노드 하나에서 막는다.
- 실시간 요약, 최종 노트와 수정 제안, 출제·채점은 그래프 없이 OpenAI SDK를 한 번 부른다.
- 노드 실행 기록은 `job_stages`에 단계 이름과 소요 시간만 남기고, AI 호출마다 `ai_calls`에 사용량을 쌓는다. LangSmith 같은 외부 추적 도구는 질문 원문이 외부로 나가므로 쓰지 않는다(SER-001 2, COR-005).
- 외부 처리 위탁 대상이 OpenAI가 되므로, COR-005 3)에 따라 OpenAI의 데이터 보관·학습 사용 조건을 확인한 뒤에 AI 기능을 출시한다.
- 자료가 늘거나 질문 유형이 다양해져 경로를 정말 예측할 수 없게 되면, 충분성 판단 구간부터 도구 선택 에이전트로 바꾼다. 그래프 구조는 그대로 두고 그 노드만 바꾸면 된다.
