# 작업 전달과 중요한 이벤트는 outbox 테이블로 보내고, 도메인 커밋 뒤 ACK한다

DB 커밋과 Redis 전송은 한 트랜잭션이 아니다. 커밋 뒤 전송 전에 프로세스가 죽으면 작업이 사라지고, 작업이 결과를 커밋한 뒤 완료 이벤트를 보내기 전에 죽으면 화면은 완료를 모른다. ADR-0001은 `jobs`를 30초마다 훑어 오래 대기한 작업을 다시 넣었다. 하지만 이 방식은 큐가 30초 이상 밀리면 이미 큐에 있는 작업까지 대량으로 다시 넣는다. 그래서 보낼 것(작업 전달, 완료·실패·취소 이벤트)을 `outbox` 테이블에 도메인 변경과 같은 트랜잭션으로 넣는다. 커밋 직후 그 자리에서 보내고 `sent_at`을 채운다. 회수 루프는 `sent_at IS NULL`인 오래된 행만 다시 보낸다. `jobs` 행에 전송 시각 열을 붙여 outbox로 쓰는 안도 있었다. 하지만 작업 전달과 이벤트를 한 곳에서 같은 방식으로 다루고 `jobs`에는 작업 상태만 두려고 별도 테이블로 했다.

## Consequences

- 보낸 직후 `sent_at`을 채우기 전에 죽으면 같은 것이 두 번 간다. 그래서 받는 쪽은 멱등이어야 한다. 작업은 lease와 `jobs` 상태로 거른다(ADR-0018). 화면은 이벤트 ID로 중복을 무시한다.
- 작업은 결과, `jobs` 완료 상태, 완료 이벤트 outbox 행을 한 트랜잭션으로 커밋한 뒤 ACK한다(ADR-0017). ACK 전에 죽어 재전달돼도 `jobs`가 이미 끝난 상태라 다시 실행하지 않는다.
- 답변 토큰과 진행 이벤트는 outbox를 거치지 않고 Redis 이벤트 Stream으로 바로 보낸다(ADR-0005). 잃어도 최종 답변은 DB에 있다.
- 사용자 요청의 재전송: 클라이언트가 요청마다 만든 요청 식별자를 `jobs (user_id, idempotency_key)` UNIQUE로 받아, 같은 키면 기존 작업을 돌려준다. 같은 키에 본문이 다르면 409를 준다. 의도적으로 다시 생성할 때는 새 키를 쓴다. 동시 실행 한도는 새 작업에만 적용한다.
- 보낸 outbox 행은 7일 뒤 `cron`이 지운다.
