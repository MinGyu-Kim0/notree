# 알림과 답변 스트리밍은 SSE, 녹음만 WebSocket으로 한다

v0.4.1의 COR-002는 실시간 연결을 WebSocket 하나로 정했지만, 변경 제안을 받아들여 연결 방식을 나눈다. 녹음 음성처럼 양방향으로 길게 이어지고 배포 중에도 끊으면 안 되는 연결만 WebSocket으로 한다. Q&A 토큰, 작업 진행, 상태 변경 같은 서버→화면 전달은 SSE로 한다. SSE 이벤트는 사용자별 Redis Stream `events:{user_id}`(최근 약 1000건)에 쌓는다. 재접속할 때는 `Last-Event-ID`를 Stream ID로 써서 놓친 이벤트를 다시 보낸다. 이미 잘려 나간 이벤트는 "전체 상태 다시 불러오기" 신호로 대신한다. 덕분에 화면 연결이 끊겨도 답변 생성은 계속되고, 재접속하면 이어서 받는다(SFR-021 4).

## Consequences (2026-11-18 추가)

- 답변 조각 이벤트에는 작업 ID와 실행 시도 번호(ADR-0018)를 붙인다. 작업이 다른 워커로 인계되면 화면은 이전 시도의 임시 답변을 비우고, 늦게 도착한 이전 시도의 조각은 버린다.
- 완료·실패·취소 같은 중요한 이벤트는 outbox를 거쳐 보낸다(ADR-0019). 중복으로 와도 화면은 이벤트 ID로 한 번만 적용한다.
- 조각을 모두 복구한다고 약속하지 않는다. 조각이 잘렸으면 '생성 중'으로 표시하고, 완료되면 최종 답변을 DB에서 불러온다.
