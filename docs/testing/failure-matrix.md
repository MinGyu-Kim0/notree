# 장애 주입 시험 계획

- 근거: [ADR-0017](../adr/0017-taskiq-delivery-sdk-retries.md)~[ADR-0019](../adr/0019-outbox-and-ack-after-commit.md), [ADR-0005](../adr/0005-sse-for-events-websocket-for-recording.md), [ADR-0006](../adr/0006-commit-time-evidence-check.md), [ADR-0007](../adr/0007-block-revisions-and-note-versions.md), [ADR-0022](../adr/0022-qa-followup-stages-in-one-job.md), [architecture.md](../architecture.md) 4·5장
- 상태: **전 항목 미실행**. 시험 설계이며 자동화 코드나 통과 결과가 아니다.
- 출처: 팀원 grilling 결과(2026-11-17)의 시험 계획을 2026-11-18 확정안(DB 실행 시도 번호 + Redis lease, 체크포인터 없음, SDK 재시도, outbox 테이블)에 맞게 고쳤다.

## 시험 조건과 기록

실제 PostgreSQL·Redis·Taskiq 워커를 쓴다. 처음에는 외부 LLM을 호출 시작·응답·지연을 제어할 수 있는 대역으로 바꾸고 호출 횟수를 기록한다. 실제 OpenAI 연동 시험은 따로 제한적으로 한다.

API, outbox 전달, 워커를 각각 종료할 수 있어야 한다. 장애 시점 앞뒤의 `jobs`·`outbox` 행, `attempt_no`, 도메인 결과 버전, 외부 호출 수, 화면 상태를 대조한다. 성공률만으로 합격 처리하지 않는다.

로그에는 작업·실행·자료 ID와 상태 전이만 남긴다. 질문·전사 원문과 키는 남기지 않는다(SER-001).

## 판정 원칙

- 무효·오래된 실행의 결과 반영과 도메인 중복 반영은 0건이어야 한다.
- 수락된 작업은 복구 뒤 실행 완료 또는 명시적 종료로 끝나야 한다. 복구 시간을 재서 목표와 비교한다.
- 외부 LLM 호출 중복은 일어날 수 있다. 호출 수와 비용을 기록하고 한도를 지켰는지 본다.
- 답변 조각의 완전 복구는 합격 조건이 아니다. 최종 상태·답변의 일치가 기준이다.
- 시간·부하 목표가 미정인 항목은 기능 통과와 성능 기준 미확정을 따로 기록한다.
